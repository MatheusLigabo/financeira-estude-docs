# Git Workflow - Bateria de Exercícios

Foque no domínio do terminal e na organização do seu histórico de código.

---

## 🎮 Prática: Side Quest (Simulação de Conflito)
Crie um repositório de teste local (`git init`).
1. Crie um arquivo `Readme.md` na branch `main` com o texto "Versão Original".
2. Crie uma branch `feature-a`. Altere a linha 1 do `Readme.md` para "Versão A" e faça commit.
3. Volte para a `main`. Altere a linha 1 para "Versão Principal" e faça commit.
4. Tente fazer `git merge feature-a` na `main`.
5. Resolva o conflito no VS Code e complete o merge.

## 📜 XP Check (10 Questões de Git e Workflow)

1. **(Git)** Qual o comando para apagar todos os meus erros locais e deixar a minha branch IGUALzinha ao servidor (`origin`)?
2. **(Workflow)** Por que é recomendável dar `git pull` na branch `main` antes de abrir um Pull Request (PR)?
3. **(Git)** O que o comando `git add .` faz exatamente?
4. **(Erro)** Você acabou de cometer um erro grave e o código nem compila mais. Qual o comando para desfazer o último commit sem apagar o que você escreveu (soft reset)?
5. **(Conflito)** O que significam as marcas `<<<<<<< HEAD` e `>>>>>>> feature-x` dentro de um arquivo durante um conflito?
6. **(Git)** Qual a diferença entre `git fetch` e `git pull`?
7. **(Histórico)** Como você visualiza os últimos commits feitos em um projeto via terminal?
8. **(Workflow)** Se você está trabalhando em algo e precisa trocar de branch urgente, mas não quer fazer commit do código incompleto, qual comando você usa para "guardar" as alterações temporariamente?
9. **(Git)** Para que serve o arquivo `.gitignore`?
10. **(PR)** O que é o "Code Review" e por que o Git é essencial para esse processo?
